# ลดปัญหาตอบช้าและหมดเวลา — 9 พฤศจิกายน 2026

สาเหตุที่พบจากบริการจริง: โมเดลโหลดไม่เสร็จก่อน client หมดเวลา การสลับขนาด context ระหว่างขั้นตีความ/ตอบ/ตรวจทำให้โหลดซ้ำ และการส่งคู่มือทั้งหน้าทำให้ข้อความของหลายการ์ดปนกัน นอกจากนี้ตัวตรวจเดิมปฏิเสธข้อสรุปโดยไม่ระบุข้อขัดแย้งหลายครั้ง รวมถึงปฏิเสธเพราะรูปแบบเครื่องหมายท้ายข้อความอ้างอิงต่างจาก PDF

## การเปลี่ยนแปลงที่ใช้ร่วมกันทุกเกม

- สถานการณ์ที่ระบุชื่อการ์ดและการกระทำครบ ไม่เรียกโมเดลตีความหัวข้อซ้ำ คำจำกัดความของการ์ดไม่ถูกเสนอเป็นคำตอบแทนคำถามสถานการณ์
- คู่มือที่มีชื่อเป้าหมายครบเป็นหลักฐานหลักในการร่างคำตอบ ส่วนกฎสรุปยังส่งให้ขั้นตรวจเพื่อพบความขัดแย้ง ไม่รวมกฎขัดกันเอง
- สำหรับหน้าคู่มือยาวที่ค้นด้วยชื่อภาษาอังกฤษ เลือกช่วงประโยคที่เกี่ยวข้องพร้อมประโยคข้างเคียง ไม่ตัดประโยคกลางกฎ คำถามที่จับช่วงข้อความไม่ได้ยังใช้ข้อความเต็ม และข้อความเต็มยังเปิดอ่านได้เสมอ เช่น หน้า Exploding Kittens 4,957 ตัวอักษร ส่งช่วงเกี่ยวกับ Attack 737 ตัวอักษรแทน
- โมเดลต้องคัดข้อความกฎใน `source_quote` ก่อนร่างคำตอบ คำถามอนุญาตเพียงประเด็นเดียวใช้ชุดคำตัดสินสั้นใน schema จึงไม่สร้างตัวอย่างหรือลำดับที่ผู้ใช้ไม่ได้ถาม ส่วนคำถามอธิบาย/หลายประเด็นยังใช้คำตอบปกติ
- ตรวจคำอ้างอิงจากต้นฉบับจริง อนุญาตความต่างด้านช่องว่าง PDF และเครื่องหมายท้ายข้อความโดยกู้ข้อความต้นฉบับกลับมา หากต้นฉบับยังมีเงื่อนไขต่อท้าย จะดึงจนจบประโยค ไม่ลบคำ ตัวเลข หรือข้อยกเว้น ตัวอ่านแสดงประโยคที่ใช้ตัดสินก่อนข้อความเต็มในอ้างอิง
- ตัวตรวจตัดสินเฉพาะประเด็นที่ถาม และยอมรับการอนุญาตตามกฎขั้นตอนที่อธิบายการเล่นนั้น ไม่ต้องมีคำว่า allowed/can ตรงตัว กรณีกฎอธิบายข้อห้ามหรือบทลงโทษไม่ถือว่าอนุญาต การปฏิเสธต้องระบุข้อขัดแย้งหรือเงื่อนไขที่ขาด และยังปฏิเสธคำตอบผิด/หลักฐานปลอมตามเดิม
- มีด่านตรวจข้อความโดยตรงเพิ่มเติม: ถ้าคำตัดสินว่าอนุญาตขัดกับรายชื่อข้อยกเว้นที่ถามถึง หรือข้อห้ามที่มีเป้าหมายตรงกัน จะไม่ส่งข้อสรุปนั้นให้ผู้ใช้และไม่เก็บเข้าแคช แม้โมเดลตรวจจะรับรองก็ตาม ด่านนี้เป็นการปฏิเสธข้อสรุปที่เสี่ยง ไม่ได้สร้างกฎตรงข้ามขึ้นเอง
- ขั้นถามตอบใช้ context อย่างน้อย 8,192 tokens ให้ตรงกัน และเก็บโมเดลพร้อมใช้ 30 นาที หัวข้อที่ต้องใช้ context ใหญ่กว่ายังไม่ถูกตัดลงเงียบ ๆ
- เก็บคำตอบสดที่ผ่านการตรวจแล้วในหน่วยความจำ 20 นาที สูงสุด 128 รายการ โดยยังเป็น `method=model` ไม่ใช่คำตอบที่มนุษย์ตรวจแล้ว คีย์รวมเกม ฐานข้อมูล โมเดล prompt ข้อความกฎทั้งหมด และประวัติที่เกี่ยวข้อง เมื่อแก้กฎแม้ข้อความอ้างอิงเดิมยังอยู่ แคชจะไม่ถูกนำกลับมาใช้ ไม่เก็บข้อผิดพลาดหรือคำตอบที่ถูกปฏิเสธ
- ข้อผิดพลาดของแชตไม่แนะนำให้แบ่งคู่มือหรือสร้างร่างเกมอีก ข้อความผิดพลาดเก่าที่บันทึกในแชตเปลี่ยนการแสดงผลให้เป็นข้อความหมดเวลาของแชต

## เครื่องที่ใช้ตรวจ

ยังใช้ `qwen3.5:4b` เดิม ได้ทดลอง `qwen3:1.7b` และ `qwen3:4b` ที่มีในเครื่อง แต่พบคำตอบผิดจึงไม่ได้เปลี่ยนมาใช้ ทดลอง GPU 20 layers ใช้ VRAM ราว 2.08 GB แต่ไม่ให้ผลรวมดีกว่าโหมด CPU สำหรับรอบที่ตรวจ จึงตั้ง `BGT_ASSISTANT_NUM_GPU=0` สำหรับบริการนี้ และให้ launcher ตั้งค่านี้ถ้ายังไม่ได้กำหนดเอง ค่า environment นี้ใช้กับ Ollama request ของผู้ช่วยเท่านั้น

## ผลที่ตรวจจริงและขอบเขต

Python 117 tests และ JavaScript 23 tests ผ่าน ครอบคลุมการเลือกช่วงพร้อมข้อยกเว้น การรักษาข้อความต้นฉบับ การไม่เปลี่ยนตัวเลข/คำปฏิเสธ การตรวจข้อขัดแย้งกับบทสรุป การบังคับ schema การไม่ใช้คำจำกัดความตอบสถานการณ์ การหมดเวลา การแคชหลังตรวจและหยุดใช้เมื่อแก้กฎ และการแสดงข้อความอ้างอิงอย่างปลอดภัย

ทดสอบลำดับ “ถ้าโดน attack สามารถใช้ attack ต่อได้ไหม” แล้วถามซ้ำหลัง “Attack คืออะไร” โดยไม่เพิ่มคำตอบนี้ลงรายการคำตอบที่มนุษย์ตรวจแล้ว ผลระหว่างพัฒนาที่ผ่านตรวจใช้ 46.9 วินาทีและถามซ้ำ 0.003 วินาที (`state/attack-latency-balanced-review-check.json`) ผล API หลังเปิดใช้จริงอยู่ `state/attack-latency-production-check.json` รวมแหล่งกฎและเวลาที่วัดจริง

รอบ API หลังเปิดใช้จริงตอบ answered ว่าอนุญาตใน 25.938 วินาที ถามซ้ำหลังคำถามนิยามได้ผลเดิมใน 0.004 วินาที ตรวจหน้าเว็บจริงแล้วแสดงคำตอบพร้อมอ้างอิงและเวลา 0.0 วินาทีจากแคช เปิดอ้างอิงพบข้อความเต็มที่กล่าวถึงการ stack และตาที่เหลือบวกอีก 2 ตา ภาพอยู่ `state/attack-latency-ui-verified.jpg` เวลานี้เป็นผลรอบตรวจ ไม่ใช่การรับรองทุกคำถามหรือทุกสภาพเครื่อง

รอบแรกยังอาจใช้เวลาหลายสิบวินาทีบนเครื่องนี้ ไม่รับประกันว่าทุกคำถามจะเร็วหรือถูกต้อง โมเดลยังตีความผิดได้ การเลือกช่วงข้อความอาจไม่ครอบคลุมทุกข้อยกเว้นจึงต้องรักษาการตรวจและเปิดต้นฉบับเต็ม ไม่อนุมัติคำตอบเป็นความรู้ที่มนุษย์ตรวจแล้วโดยอัตโนมัติ

ตรวจเชิงลบด้วยการเสนอคำตอบผิดว่า Nope ใช้กับ Defuse ได้ พบว่าตัวตรวจโมเดลรับรองผิด (`state/assistant-negative-review-check.json`) จึงไม่ถือว่าโมเดลตรวจเป็นหลักประกันความถูกต้อง เพิ่มด่านข้อยกเว้นด้านบนแล้วทดสอบ replay กับข้อความคู่มือจริง โดยจำลองข้อเสนออนุญาตที่ผิดและตัดรายการคำตอบตรวจแล้วออกเฉพาะในสำเนาทดสอบ ไม่แก้ฐานข้อมูลจริง ระบบปิดกั้นก่อนส่งให้ตัวตรวจโมเดล/ก่อนเก็บแคช (`state/assistant-negative-pipeline-check.json`) ผลนี้ไม่ได้หมายความว่าด่านข้อความครอบคลุมการตีความทุกภาษาและทุกเงื่อนไข
