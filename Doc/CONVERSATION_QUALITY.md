# ปรับคุณภาพบทสนทนา — 9 พฤศจิกายน 2026

ปรับกลไกที่ใช้ร่วมกันทุกเกม ไม่มีการเพิ่มคำตอบสำเร็จรูปสำหรับคำถามในภาพ และไม่ได้เปลี่ยนกฎหรือเพิ่มคำตอบที่รับรองแล้วในฐานข้อมูล

## การตีความและหลักฐาน

- คำถามสถานการณ์ต่อเนื่องผ่านขั้นตีความแยกจากการตอบกฎ โดยเห็นเฉพาะคำถามล่าสุดและคำถามก่อนหน้าสองข้อ ไม่เห็นคำตอบเก่าหรือข้อสรุปกติกา ขั้นนี้ระบุหัวข้อการ์ด/บทบาทแยกไว้ ถ้ามีหลายความหมายให้ถามรายละเอียดหนึ่งประเด็น
- ก่อนนำคำถามที่ตีความแล้วไปค้น ต้องรักษาข้อความการกระทำ คำปฏิเสธ จำนวน และช่วงเวลาของคำถามล่าสุด หากไม่ผ่าน จะขอรายละเอียดแทนการใช้คำถามที่โมเดลเปลี่ยนความหมาย
- หลังตีความแล้ว ไม่ส่งคำตอบเก่าทั้งหมดกลับไปชี้นำโมเดลตอบกฎ ใช้หัวข้อที่ระบุได้ร่วมกับคำถามปัจจุบัน
- การจับคู่คำตอบตรวจแล้วเพิ่มตัวกรองคำปฏิเสธและก่อน/หลัง คำถามที่เปลี่ยนเงื่อนไขยังค้นกฎมาตอบได้ แต่ไม่เลือกข้อสรุปเก่ามาใช้โดยอัตโนมัติ คำถามหรือ alias ที่ตรวจไว้ตรงตัวคงเส้นทางเดิม
- Q&A ที่ค้นพบพาไปยังแหล่งกฎต้นฉบับ ไม่ส่งคำถามและคำตอบเก่าเป็นหลักฐานสำหรับคำถามใหม่ที่ยังไม่ได้ยืนยันว่าเจตนาเดียวกัน
- คำตอบที่เคยเป็น excerpt, insufficient หรือ error ไม่ถูกส่งเป็นคำตอบบริบท และแหล่งอ้างอิงของคำตอบที่ยังยืนยันไม่ได้ไม่ถูกสืบทอดเป็นข้อสรุปเดิม
- ตัวตรวจคำตอบเห็นคำถามล่าสุด หัวข้อที่ตีความ และบริบทที่จำเป็น ตรวจทั้งความตรงกับหลักฐานและความตรงกับสถานการณ์ที่ถาม

## การแสดงคำตอบ

เมื่อคำตอบไม่ผ่านการตรวจ ระบบแสดงข้อความสั้นพร้อมสถานะ “ยังยืนยันคำตอบไม่ได้” และเก็บกฎต้นฉบับไว้ในอ้างอิง ไม่คัดคำถาม–คำตอบเก่าหรือรายละเอียดการตรวจของโมเดลมาวางเป็นคำตอบ ผู้ใช้เปิด “ดูกฎอ้างอิง” เพื่ออ่านชื่อหัวข้อ ฉบับ ข้อความเต็ม และลิงก์คู่มือได้ โดยไม่ต้องเห็นรหัสภายในหรือชื่อประเภทที่ซ้ำกันตลอดแชต

แชตเก่าที่บันทึก fallback รูปแบบเดิมยังเก็บข้อมูลไว้ แต่เปลี่ยนวิธีแสดงผลให้สั้นและชัดว่าไม่ใช่ข้อสรุป ไม่ต้องล้างประวัติเพื่อให้เห็นรูปแบบใหม่ โหมดสาธิตยังแสดงข้อความกฎและมีป้ายแยกชัดเจน

## การตรวจ

- Python 103 tests ผ่าน รวม regression เรื่องการเปลี่ยนการกระทำ คำปฏิเสธ จำนวน ก่อน/หลัง การรักษาหัวข้อ การถามรายละเอียดโดยไม่ค้น/ตอบกฎก่อน และการไม่ใช้คำตอบเก่าเป็นหลักฐาน
- JavaScript 21 tests ผ่าน รวมข้อความสถานะ อ้างอิงพับได้ การแสดงประวัติ fallback เดิม และการ escape HTML/ปฏิเสธลิงก์ที่ไม่ปลอดภัย
- ตรวจหน้าเว็บจริง: ส่งคำถามที่ตรวจแล้ว เปิดอ่านคู่มือครบ แล้วพับอ้างอิงกลับได้ ภาพอยู่ `state/conversation-ui-after.jpg`
- ทดสอบโมเดลจริงกับคำถามต่อเนื่องสี่เกม ได้แก่ คำต้องห้าม Mogel Motte Werewolf และ For Sale รายงานระหว่างพัฒนาอยู่ `state/conversation-quality-*.json` มีทั้ง timeout, ผลตรวจที่ปฏิเสธข้อสรุป และปัญหารูปแบบ JSON ของขั้นตีความที่แก้เป็น schema บังคับ status/subject/question แล้ว
- ตรวจ endpoint จริงหลังเปิดใช้ขั้นตีความ: เมื่อถามต่อจากการเปรียบเทียบการ์ดสองใบด้วยคำว่า “มัน” ระบบขอระบุสิ่งที่หมายถึงและไม่สร้างคำตอบกฎ ผลล่าสุดอยู่ `state/conversation-quality-activation-check.json`

การทดสอบสี่เกมไม่ได้หมายความว่าคำตอบกฎถูกต้องทั้งหมด โมเดลยังสร้างข้อสรุปเกินหลักฐานในหลายกรณีและตัวตรวจปฏิเสธให้เป็นข้อความสั้น ผลเหล่านั้นเป็นหลักฐานว่าต้องคงการตรวจและแจ้งข้อจำกัด ไม่ใช่ผลสอบความแม่นยำผ่านทุกข้อ เวลาอาจยังหลายสิบวินาที ไม่รับประกันว่าขั้นตีความจะเข้าใจทุกประโยคหรือถามรายละเอียดได้เหมาะสมเสมอ

เปิดใช้โค้ดล่าสุดบน Backend แล้ว โดยส่งต่อ environment และรหัสผู้ดูแลเดิมในหน่วยความจำ ไม่แสดงหรือบันทึกรหัสผ่าน ผู้ดูแลต้องเข้าสู่ระบบใหม่หลังรีสตาร์ต หน้าเว็บที่เปิดค้างให้กด Ctrl+F5

## คำถามสั้นที่ละหัวข้อและการเทียบจำนวน

ขยายขั้นตีความให้รับคำถามสั้นที่ไม่มีคำขึ้นต้นว่า “ถ้า” เช่น จำนวนครั้ง/ไพ่/คน และการถามถึงอีกคนหรืออีกใบ โดยต้องมีบทสนทนาก่อนหน้า คำถามใหม่ที่ระบุหัวข้อครบยังค้นตามหัวข้อปัจจุบัน

สำหรับคำถามที่เปลี่ยนเพียงจำนวน ใช้การเปรียบเทียบโดยตรงได้เมื่อหัวข้อเดิมตรงคำถามหรือ alias ที่ตรวจแล้ว หน่วยตรงกัน จำนวนในคำตอบและข้อความหลักฐานตรงกัน และจำนวนที่ถามเกินกฎเท่านั้น ไม่อนุมานว่าจำนวนที่น้อยกว่าถูกอนุญาต ไม่ใช้ทางลัดเมื่อมีข้อยกเว้น ขอบเขตขั้นต่ำ หลักฐานเปลี่ยน หรือเปลี่ยนหัวข้อ รองรับคำถามจำนวนต่อกันหลายข้อความจนมีหัวข้อใหม่ ไม่มีเงื่อนไขแยกตามชื่อเกม

ตรวจ API จริง: คำต้องห้าม/สองครั้ง และ Werewolf/สองคน ตอบไม่อนุญาตพร้อมกฎที่ยืนยันไว้ในประมาณ 0.005–0.006 วินาทีของรอบตรวจนี้ ไม่เรียกโมเดล ผลอยู่ `state/short-followup-verification.json` และตรวจบนหน้าเว็บจริงด้วยลำดับคำถามในภาพแล้ว ตอบตรงกับกฎและแสดงเวลา 0.0 วินาที ภาพอยู่ `state/short-followup-ui-verified.jpg` กรณีอื่นที่ไม่ผ่านเงื่อนไขทางลัดยังใช้ขั้นตีความและตรวจคำตอบตามเดิม
