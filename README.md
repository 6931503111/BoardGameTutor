# BoardGameTutor

## Backend ฐานข้อมูลเกม (ระยะเริ่มต้น)

ระยะนี้ใช้ FastAPI และ SQLite สำหรับพัฒนาในเครื่อง ข้อมูลเกมที่สร้างหรือแก้ไขจากหน้าแอดมินจะถูกบันทึกที่ `backend/data/games.sqlite3` เกมตัวอย่างเริ่มต้นอยู่ในหน้าเว็บและนำเข้าได้จากหน้าแอดมิน

### เริ่มระบบในเครื่อง

ติดตั้ง dependencies จากโฟลเดอร์รากของ repository:

```powershell
python -m pip install -r backend/requirements.txt
```

กำหนดรหัสผ่านผู้ดูแลสำหรับหน้าต่าง PowerShell ปัจจุบัน แล้วเปิด Backend:

```powershell
$env:BGT_ADMIN_PASSWORD = "ตั้งรหัสผ่านที่คาดเดายาก"
python -m uvicorn backend.app:app --reload --host 127.0.0.1 --port 8000
```

อย่าใส่รหัสผ่านจริงลงใน source code หรือ commit ไฟล์ที่มีรหัสผ่าน

เปิดเว็บสถิตในหน้าต่าง PowerShell ที่สอง:

```powershell
python -m http.server 5500 --directory Code
```

จากนั้นเปิด `http://127.0.0.1:5500` ในเบราว์เซอร์ หน้าเว็บบน localhost จะเชื่อม Backend ที่ `http://127.0.0.1:8000` อัตโนมัติ

หลังเข้าสู่ระบบผู้ดูแล ให้กด **นำเข้าเกมตัวอย่างลงฐานข้อมูล** ในหน้าจัดการเนื้อหา เกมตัวอย่างที่ยังไม่มีจะถูกเพิ่มเข้า SQLite; เกมที่มีรหัสเดิมในฐานข้อมูลจะถูกข้ามและไม่ถูกเขียนทับ การนำเข้าซ้ำจึงปลอดภัย

### สร้างฉบับร่างเกมด้วย AI

ติดตั้งและเปิด Ollama บนเครื่องที่รัน Backend จากนั้นดึงโมเดลที่ต้องการ โมเดลเริ่มต้นคือ `qwen3:1.7b`:

```powershell
ollama pull qwen3:1.7b
```

เมื่อเปิด Backend ให้ตั้งค่า URL และชื่อโมเดลได้ด้วย `BGT_OLLAMA_URL` และ `BGT_OLLAMA_MODEL` (ค่าเริ่มต้นคือ `http://127.0.0.1:11434` และ `qwen3:1.7b`) ในหน้าแอดมินใส่ชื่อเกมแล้วอัปโหลด PDF ระบบจะอ่านข้อความและปรับรหัสอักขระฟอนต์ไทยบางรูปแบบที่พบบ่อยโดยไม่เขียนเนื้อหาใหม่ จากนั้นแสดงข้อความให้ตรวจและแก้ไขก่อนให้ AI สร้างร่างเกม รองรับไฟล์ไม่เกิน 20 MB, 200 หน้า และข้อความไม่เกิน 100,000 ตัวอักษร ไฟล์สแกนจะลอง OCR ในเบราว์เซอร์อัตโนมัติเมื่อ API ดึงข้อความไม่ได้ โดยใช้ PDF.js และ Tesseract.js ภาษาไทย+อังกฤษ อ่านได้ครั้งละไม่เกิน 40 หน้า หากข้อความจากไฟล์ขาดหายหรือผิดเพี้ยนให้เลือก **ใช้ OCR ทุกหน้า** ก่อนอ่านไฟล์ OCR ทำงานในเครื่อง แต่ต้องใช้อินเทอร์เน็ตดาวน์โหลดไลบรารีและข้อมูลภาษา ไม่ส่งภาพไปบริการ OCR ภายนอก แสดงความคืบหน้าและยกเลิกได้ ข้อความ OCR ต้องตรวจตัวเลข ตัวอักษร และลำดับคอลัมน์เทียบต้นฉบับก่อนสร้างร่าง (OCR นี้ใช้ผ่านหน้าเว็บ ส่วน API อ่าน PDF โดยตรงยังอ่านเฉพาะชั้นข้อความ) การปรับอักขระนี้แก้ได้เฉพาะรูปแบบที่รู้จัก จึงควรตรวจข้อความและ JSON ก่อนบันทึก ระบบสร้างบทเรียน/กฎในรูปแบบที่หน้าเว็บใช้ พร้อมการ์ดภาพประกอบที่อิงจากคู่มือ และเกมจะถูกบันทึกเป็นฉบับร่างโดยไม่เผยแพร่เอง

ตรวจสอบ API ได้ที่ `http://127.0.0.1:8000/docs` และรันทดสอบด้วย:

```powershell
python -m unittest backend.tests.test_api
```

ทดสอบการนำเข้า PDF และ OCR (ใช้ Node.js โดยไม่ต้องโหลดโมเดล OCR):

```powershell
node --test backend/tests/test_pdf_ocr.cjs
```

การนำเข้าเกมจะแยกสร้างโจทย์เพิ่มเติมจากกติกาต้นฉบับ หากร่างแรกไม่มีสถานการณ์หรือข้อสอบ จึงอาจใช้เวลามากขึ้น หากสร้างโจทย์ไม่สำเร็จ ระบบยังแสดงร่างกฎที่สร้างได้และแจ้งเตือนให้ลองเพิ่มโจทย์ภายหลัง ผู้ดูแลควรตรวจคำตอบและเหตุผลเทียบคู่มือทุกครั้ง

การสร้างร่างและโจทย์ส่ง JSON schema ให้ Ollama และตรวจคำตอบก่อนแสดง หากรูปแบบผิดหรือคำตอบถูกตัด ระบบลองใหม่อีก 1 ครั้งโดยเพิ่มงบคำตอบ หากยังไม่สำเร็จ จะแสดงสาเหตุค้างใต้ปุ่มสร้างร่าง โดยเก็บข้อความคู่มือไว้ให้ลองใหม่ ข้อผิดพลาดแยกการเชื่อมต่อไม่ได้ โมเดลไม่พบ คำตอบถูกตัด และชื่อช่องข้อมูลที่ไม่ผ่านการตรวจ

หากเกมที่นำเข้ามีกฎแต่ไม่มีบทเรียน ระบบใช้หัวข้อกฎเดิมเป็นบทเรียนทีละขั้นโดยคงข้อความไว้ทั้งหมด รวมถึงเกมที่บันทึกก่อนอัปเดต ปุ่มทดสอบแสดงจำนวนข้อสอบ และกำหนดให้เรียนครบเฉพาะเกมที่มีบทเรียน หากยังไม่มีข้อสอบจะแสดงคำแนะนำให้ผู้ดูแลสร้างเพิ่มสำหรับเกมนั้น

เพิ่มหรือเปลี่ยนรูปเกมได้ที่ **ผู้ดูแลระบบ → เกมทั้งหมด → รูปปกหรือตัวเกม** รองรับ JPG, PNG และ WebP ไม่เกิน 2 MB ระบบบันทึกรูปพร้อมข้อมูลเกมและแสดงในรายการเกมกับหน้ารายละเอียด ใช้ได้ทั้งเกมเดิมและเกมที่เพิ่มใหม่

สำหรับเกมที่มีอยู่แล้ว ไปที่ **ผู้ดูแลระบบ → สร้างโจทย์ด้วย AI ให้เกมที่มีอยู่** เลือกเกม แล้วกด **สร้างร่างโจทย์จากกติกา** ระบบใช้กฎและบทเรียนที่บันทึกไว้ หรือใช้ข้อความคู่มือเพิ่มเติมที่ผู้ดูแลวางแทน เมื่อดูตัวอย่างโจทย์และเฉลยแล้ว สามารถแก้ JSON และกด **ตรวจสอบแล้ว และเพิ่มโจทย์** เพื่อเพิ่มต่อท้ายของเดิม โดยคงสถานะเผยแพร่และเนื้อหาเกมเดิมไว้ ไม่ต้องอัปโหลดเกมใหม่ API `POST /api/admin/generate-practice` สร้างเฉพาะร่างและต้องใช้สิทธิ์ผู้ดูแล

หน้ากฎและบทเรียนแสดงย่อหน้าและรายการจากข้อความ และใช้การ์ดที่ปรับความกว้างตามหน้าจอ รูปแบบนี้ใช้กับเกมเดิมด้วยเมื่อรีเฟรชหน้าเว็บ ส่วนการแบ่งย่อหน้าจาก AI แบบใหม่จะมีผลกับเนื้อหาที่สร้างหลังอัปเดต

ลบเกมได้จาก **ผู้ดูแลระบบ → เกมทั้งหมด → ลบเกม** ระบบแสดงชื่อเกมและขอยืนยันก่อนลบถาวร พร้อมลบประวัติและความคืบหน้าของเกมในเบราว์เซอร์ที่ใช้งาน เมื่อเชื่อม Backend สำเร็จ รายการเกมจะใช้ข้อมูลจากฐานข้อมูลเท่านั้น เพื่อไม่ให้เกมที่ลบกลับมาจากเกมตัวอย่างในหน้าเว็บ ฐานข้อมูลว่างสามารถเพิ่มเกมผ่าน PDF หรือกดนำเข้าเกมตัวอย่างได้ API ลบเกม `DELETE /api/games/{game_id}` ต้องใช้สิทธิ์ผู้ดูแล

### ผู้ช่วยกฎเกมและคำถามต่อเนื่อง (FR-5 / FR-8)

เปิด **ผู้ช่วย AI** หรือ **ถามผู้ช่วย AI** จากหน้าเกม แล้วพิมพ์คำถาม กรณีรันพร้อม Backend หน้าเว็บเรียก `POST /api/games/{game_id}/ask` ซึ่งค้นจากกฎและบทเรียนของเกมนั้นใน SQLite เท่านั้น ไม่ค้นเกมอื่น คำตอบแสดงหัวข้อและข้อความอ้างอิงที่กดเปิดอ่านได้ โดยเป็นข้อความในฐานความรู้ที่บันทึกไว้ ไม่ใช่การรับรองว่าผ่านการตรวจคู่มือฉบับทางการแล้ว

ร่างเกมที่นำเข้าใหม่เก็บข้อความกติกาที่ตรวจแล้วใน `source_text` ด้วย ระบบค้นข้อความคู่มือนี้เพิ่มเติมจากกฎ/บทเรียนและแสดงเลขหน้าเมื่อมี marker จาก PDF เกมเก่าที่ไม่เคยเก็บข้อความต้นฉบับยังใช้ข้อมูลที่มีอยู่ ตัวเลขสมมติในคำถามไม่จำเป็นต้องตรงกับตัวเลขที่อยู่ในคู่มือ เช่น สามารถนำกฎ “ต้องเสนอมากกว่าราคาล่าสุด” มาเปรียบเทียบจำนวนเงินในสถานการณ์ได้ เมื่อข้อมูลรองรับเพียงบางส่วน จะแสดงสถานะ **คำตอบและข้อจำกัด** เพื่อแยกสิ่งที่ยืนยันได้จากสิ่งที่ยังไม่ระบุ

สำหรับกฎประมูลที่ระบุชัดว่าต้องเสนอมากกว่าราคาล่าสุด ระบบคำนวณการเปรียบเทียบจำนวนเงินโดยตรงและอ้างอิงกฎนั้น ไม่ให้โมเดลตรวจซ้ำจนปัดผลคำนวณทิ้ง รองรับจำนวนเงินที่มีจุลภาคและหน่วยพัน/หมื่น/แสน/ล้าน หากบอกเพียงเงินที่มี จะถามราคาล่าสุดและราคาเสนอเพิ่ม เงื่อนไขนี้ใช้เฉพาะเกมที่มีหลักฐานกฎดังกล่าว ไม่สันนิษฐานว่าเกมประมูลทุกเกมใช้กฎเหมือนกัน

ระบบส่งประวัติที่เกี่ยวข้องและรหัสหลักฐานเดิมเพื่อช่วยตีความคำถามต่อเนื่อง เช่น ถาม “Nope คืออะไร” แล้วถาม “ขอยกตัวอย่างเพิ่ม” บทสนทนาแยกตามเกม และปุ่ม **เริ่มบทสนทนาใหม่** ล้างบริบทของเกมปัจจุบัน คำตอบที่มาถึงหลังล้างแชตจะไม่ถูกใส่กลับมา หากเปลี่ยนเกมระหว่างรอ คำตอบยังถูกเก็บในแชตของเกมเดิม

คำถามกำกวมจะขอรายละเอียดเพิ่ม และเมื่อไม่พบหลักฐานจะระบุว่ายังยืนยันไม่ได้ กรณี AI ไม่พร้อมใช้งานจะแสดงข้อผิดพลาดแยกจากคำตอบตามกฎ โหมดสาธิตแสดงข้อความต้นฉบับที่ค้นพบโดยไม่เรียกโมเดล เมื่อใช้ Backend URL ของ Ollama มาจาก `BGT_OLLAMA_URL` ส่วนโมเดลถามตอบเลือกจาก `BGT_ASSISTANT_MODEL` ก่อน แล้วจึงใช้ `BGT_OLLAMA_MODEL` หากตั้งไว้ หากไม่ตั้งทั้งสองตัวใช้ `qwen3.5:4b` (ต้องมีโมเดลในเครื่อง เช่น `ollama pull qwen3.5:4b`) และตรวจข้อยกเว้นกับหลักฐานซ้ำก่อนแสดงคำตอบ โมเดลสร้างร่างเกมยังมีค่าเริ่มต้นเป็น `qwen3:1.7b` ค่าบนหน้าเว็บสำหรับเชื่อม Ollama โดยตรงใช้เฉพาะกรณีไม่มี Backend

ก่อนแสดงข้อสรุป ระบบตรวจซ้ำว่าคำตอบสอดคล้องกับหลักฐานและให้โมเดลคัดข้อความจากกฎมาเป็นหลักฐานตรวจสอบ หากข้อความที่อ้างไม่ตรงต้นฉบับหรือตรวจยืนยันไม่ได้ ระบบแจ้งข้อจำกัดพร้อมแสดงกฎที่ค้นพบ การค้นใช้ทั้งคำภาษาไทย/อังกฤษและ multilingual embedding ผ่านโมเดล `embeddinggemma` ใน Ollama โดยค้นเฉพาะเกมที่เลือกและเก็บเวกเตอร์ตาม hash ของข้อความ เมื่อแก้คู่มือจะสร้างเวกเตอร์ใหม่เฉพาะข้อความที่เปลี่ยน หากโมเดล embedding ใช้ไม่ได้จะกลับไปค้นด้วยคำ การตรวจซ้ำนี้ยังใช้โมเดล จึงไม่ได้รับประกันว่าตีความกฎถูกทุกครั้ง

ทดสอบ FR-5 / FR-8 ด้วย `python -m unittest backend.tests.test_rule_assistant` และ `node --test backend/tests/test_chat.cjs`

### เตรียมพรีเซนต์และเพิ่มฐานความรู้

อ่านขั้นตอนเปิดระบบและขอบเขตทั้งหกเกมใน [คู่มือพรีเซนต์](Doc/PRESENTATION_GUIDE.md)
เปิดบริการที่ยังไม่ทำงานด้วย `powershell -File scripts/Start-Presentation.ps1` แล้วเข้า `http://127.0.0.1:5500`
ตรวจบริการจริงและโมเดลที่ Backend ใช้ด้วย `python scripts/presentation_check.py` สำรองฐานข้อมูลอย่างสอดคล้องแม้บริการกำลังทำงานด้วย `python scripts/backup_games.py`

ผู้ดูแลเพิ่มคู่มือให้เกมเดิมได้ที่ **คู่มือสำหรับผู้ช่วย AI** โดยใส่ชื่อฉบับและลิงก์แหล่งข้อมูลด้วย
ส่วน **คำตอบที่ตรวจเทียบกฎแล้ว** ใช้เพิ่มคำถาม คำตอบ และคัดข้อความหลักฐานตรงจากกฎ ต้องตรวจคำตอบเองก่อนทำเครื่องหมายยืนยัน ระบบไม่อนุมัติคำตอบที่ AI สร้างเองอัตโนมัติ
คำถามที่ตรงหรือเป็น alias ที่ระบุไว้จะตอบทันทีพร้อมป้ายกำกับ หากใช้ถ้อยคำต่างกัน โมเดลจะช่วยจับคู่เจตนาและแสดงคำถามต้นแบบพร้อมคำตอบที่ตรวจแล้ว โดยไม่เขียนคำตอบนั้นใหม่ มีการตรวจชื่อเป้าหมายและตัวเลขก่อนจับคู่เพื่อป้องกันคำถามที่เปลี่ยนเงื่อนไข ส่วนคำถามอื่นค้นได้ทั้งคู่มือ บทเรียน กฎ และคำอธิบายที่ตรวจแล้ว หากข้อความหลักฐานเปลี่ยนหรือถูกลบ คำตอบที่พึ่งหลักฐานนั้นจะหยุดใช้จนตรวจใหม่
รายการ **ตรวจข้อมูลผู้ช่วย AI ทุกเกม** ตรวจความครบของข้อมูลและจำนวนคำตอบที่ยังใช้ได้ เป็นการตรวจข้อมูล ไม่ใช่การทดสอบความแม่นยำของโมเดล

เกมใหม่ใช้กระบวนการเดียวกันโดยไม่ต้องเพิ่มเงื่อนไขแยกตามชื่อเกม: นำเข้า PDF → ตรวจข้อความและฉบับ → ตรวจร่างกฎ/แบบฝึก → ทดสอบคำถามและคำถามต่อเนื่อง → เผยแพร่
การอัปโหลดอย่างเดียวไม่ได้รับประกันว่าข้อความ OCR หรือคำตอบ AI ถูกต้อง โมเดลในเครื่องยังอาจตีความผิดแม้มีการตรวจซ้ำ

### ขอบเขตการใช้งานในเครื่อง

- SQLite ในระยะนี้เก็บข้อมูลถาวรบนเครื่องที่รัน Backend เท่านั้น ยังไม่ซิงก์ข้ามเครื่อง
- GitHub Pages ยังคงใช้พื้นที่จัดเก็บของเบราว์เซอร์ จนกว่าจะนำ Backend ไปโฮสต์และกำหนด URL API ให้หน้าเว็บ
- API เขียนเกมต้องเข้าสู่ระบบผู้ดูแลก่อน รหัสผ่านมาจาก `BGT_ADMIN_PASSWORD`; token มีอายุ 8 ชั่วโมงและถูกยกเลิกเมื่อ Backend รีสตาร์ต
- ระบบนี้ยังไม่มี rate limiting, HTTPS หรือระบบจัดการผู้ดูแลหลายบัญชี จึงตั้งใจให้รันบน `127.0.0.1` เพื่อพัฒนาในเครื่องเท่านั้น **อย่าเปิด Backend สู่เครือข่ายสาธารณะก่อนตั้ง HTTPS, rate limiting และมาตรการ production เพิ่มเติม**
